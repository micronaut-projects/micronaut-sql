When you use api:configuration.mybatis.MyBatisMapperScan[] (see <<mybatis-customizers, Configuring MyBatis customizers>>), the `micronaut-mybatis-processor` generates the GraalVM metadata for your mappers:

* every mapper interface is registered as a dynamic proxy, because MyBatis implements mappers with `java.lang.reflect.Proxy`
* the result and parameter types of the mapper methods (unwrapping arrays, collections, maps, `Optional` and reactive publishers) are registered for reflection, because MyBatis instantiates and populates them reflectively

The metadata is generated through the same mechanism as `@ReflectiveAccess`, which requires `micronaut-graal` on the annotation processor path; the Micronaut Gradle and Maven plugins add it automatically for native image builds. It is ignored when running on the JVM, so no manual configuration is needed for the common case. Set `nativeImageMetadata = false` on the annotation if you prefer to manage the native image configuration yourself.

Types that MyBatis reaches only through mapping metadata rather than method signatures still have to be registered manually, for example the `javaType` of a `@Result`, association or collection types of nested result maps, or custom type handlers and object factories. Annotate such classes with `@ReflectiveAccess`, or declare them in your own `reflect-config.json`.

Mapper interfaces registered by MyBatis runtime package scanning (`configuration.addMappers(String)`) are not supported in native images.
